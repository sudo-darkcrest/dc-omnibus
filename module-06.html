Operating Systems: Windows, macOS, Linux, Mobile

Why this matters. Operating systems are the biggest domain on A+ Core 2, and they are where most support tickets end up: a slow PC, a broken update, a permissions error, a lost file. You need to know where every tool lives, which command fixes what, how file systems and permissions work, and how to troubleshoot methodically. The same skills carry into server administration, cloud and security work.

You will be able to

  • Explain what an OS does: kernel, drivers, processes, memory management, virtual memory, file systems and permissions.
  • Use the main Windows tools and commands (Task Manager, Event Viewer, Device Manager, ipconfig, sfc, DISM, robocopy and more).
  • Choose file systems and partition schemes (NTFS, exFAT, ext4, APFS; MBR vs GPT).
  • Use core macOS and Linux tools and read Linux permissions in symbolic and octal form.
  • Apply the CompTIA 7-step troubleshooting method to common OS problems.
  • Design a backup plan using full, incremental, differential and synthetic backups and the 3-2-1 rule.

Cert map

1. What an operating system does

  • Kernel: the privileged core. It runs in kernel mode (full hardware access); apps run in user mode and ask the kernel for services through system calls. This separation stops a crashing app from taking down the whole machine.
  • Drivers: kernel modules that control specific hardware. A bad driver is a top cause of blue screens.
  • Processes and threads: the OS creates, schedules and ends them (Module 4).
  • Memory management: each process gets its own virtual address space. The OS and CPU's memory management unit (MMU) map virtual pages (usually 4 KiB) to physical RAM. When RAM is full, rarely used pages move to disk: the page file (Windows pagefile.sys) or swap (Linux). Touching a page that is on disk causes a page fault, and constant paging ("thrashing") makes a PC crawl.
  • File systems: organize data on storage into files and folders with metadata (names, sizes, timestamps, permissions).
  • Security and permissions: users, groups, access control lists, privilege elevation.

PowerShell is the modern shell: commands are cmdlets named Verb-Noun (Get-Process, Get-Service, Test-NetConnection, Get-ChildItem) and pass objects, not text, through the pipeline. Scripts end in .ps1; the execution policy controls whether they run.

Accounts, security and domains

  • Account types: local accounts, Microsoft accounts, domain (Active Directory) or Entra ID accounts. Standard users vs administrators.
  • UAC (User Account Control): prompts before changes needing admin rights, so even admins run with standard rights by default.
  • BitLocker: full-volume encryption using the TPM; BitLocker To Go for removable drives. Store the 48-digit recovery key safely (Microsoft account, AD/Entra ID, printout).
  • Microsoft Defender Antivirus and Defender Firewall (domain, private, public profiles).
  • Workgroup vs domain: a workgroup is peer-to-peer with local accounts on each PC (fine for under ~20 PCs). A domain uses Active Directory Domain Services on domain controllers for central accounts, Group Policy, and organizational units (OUs). Users log on with DOMAIN\user and roaming profiles or folder redirection can follow them.
  • Shares and permissions: NTFS permissions apply locally and over the network; share permissions apply only over the network. The most restrictive of the two wins. Administrative shares end with $ (C$, ADMIN$).

4. macOS

  • Finder (file manager), Spotlight (Cmd+Space search), Dock, Mission Control, System Settings (formerly System Preferences).
  • Time Machine: automatic hourly/daily/weekly backups to an external disk or network share.
  • FileVault: full-disk encryption.
  • Keychain (Keychain Access / Passwords app): stores passwords, certificates and keys.
  • Terminal: zsh shell with Unix commands; Disk Utility (First Aid, partitioning, formatting); Activity Monitor (like Task Manager); Console (logs); Boot Camp (Windows on older Intel Macs).
  • Apps install from the App Store or as .dmg (mount, drag to Applications) or .pkg installers. Gatekeeper checks app signatures.
  • Recovery: hold Cmd+R at startup on Intel Macs; on Apple silicon, hold the power button for options.

5. Linux

Linux is a kernel; a distribution bundles it with tools, a package manager and defaults: Debian/Ubuntu (apt, .deb), Red Hat/Fedora/Rocky/Alma (dnf, .rpm), SUSE (zypper), Arch (pacman).

Permissions: rwx and octal

Each file has an owner, a group and three permission sets: owner (u), group (g), others (o). Each set has read (4), write (2) and execute (1). Add them per set: rwx = 7, r-x = 5, r-- = 4. So chmod 755 script.sh = rwxr-xr-x. For directories, x means "may enter the folder".

6. Mobile operating systems

  • Android (Google; Linux kernel; many manufacturers; Google Play plus sideloading of .apk files) and iOS/iPadOS (Apple only; App Store; tightly controlled).
  • MDM (mobile device management) and MAM (mobile application management): enroll devices, push apps and Wi-Fi/VPN profiles, enforce passcodes and encryption, remote wipe, separate work and personal data (Android Work Profile, Apple managed apps).
  • Sync and backup: iCloud, Google account backup, Microsoft 365 / Exchange ActiveSync for mail, contacts and calendars; local backups via computer.
  • Security: screen locks (PIN, biometrics), full-device encryption (default on modern phones), OS updates, app permissions, locator apps (Find My, Find My Device), avoid jailbreaking/rooting.

7. Software: installation, licensing and patching

  • Install considerations: system requirements (CPU, RAM, storage, 32 vs 64-bit), OS compatibility, distribution method (download, ISO, MSI, store, package manager), impact on the device, network and business, and the need for admin rights.
  • Licensing: EULA (end-user license agreement), per-user vs per-device, perpetual vs subscription, volume/enterprise licensing, open source (GPL copyleft vs permissive MIT/Apache), freeware vs shareware. Using unlicensed software is a legal and security risk.
  • Updates and patches: security updates, feature updates, driver and firmware updates. Test before broad deployment, schedule maintenance windows, keep a rollback plan (Module 8 change management).

8. Troubleshooting methodology and common OS problems

The CompTIA 7 steps

  1. Identify the problem: gather information from the user, identify changes, back up data before making changes, inquire about environmental or infrastructure changes.
  2. Establish a theory of probable cause (question the obvious; research if needed).
  3. Test the theory to determine the cause. If confirmed, determine next steps; if not, establish a new theory or escalate.
  4. Establish a plan of action to resolve the problem and implement the solution, referring to vendor instructions as needed.
  5. Implement the solution or escalate as appropriate.
  6. Verify full system functionality and, if applicable, implement preventive measures.
  7. Document findings, actions, outcomes and lessons learned.
Backing up data comes in step 1, before you change anything. Documentation is the LAST step (7), even though you take notes all along.

9. Backups

TypeBacks upArchive bit (Windows)To restore you need
FullEverything selectedClearedThat one full backup
IncrementalChanges since the last backup of any typeClearedLast full + every incremental since
DifferentialChanges since the last fullNot clearedLast full + the latest differential
Synthetic fullBuilt on the backup server by merging a full with later incrementalsn/aThat synthetic full (no need to re-read the source)

3-2-1 rule: keep 3 copies of data, on 2 different media types, with 1 copy off-site (many now add "1 immutable or offline copy, 0 errors after verification" for ransomware resilience). Also consider retention (how long to keep backups), frequency, and testing restores: a backup you have never restored is a hope, not a plan.

Key terms

Memory aids

7 steps: I Eat Tacos, Enjoy Ice cream, Verify, Document → Identify, Establish theory, Test, Establish plan, Implement, Verify, Document.
Permissions: r=4, w=2, x=1. 7 = rwx, 6 = rw-, 5 = r-x, 4 = r--. "Seven is everything, six can't run, five can't write."
Restore: Incremental = Inconvenient restore (all of them). Differential = Decent restore (full + latest one).
sfc vs DISM: "DISM Doctors the store, then sfc swap files."
Exam trapWhy it is wrong
"Use FAT32 for a 10 GB disk image file."FAT32 cannot hold a file over 4 GiB; use exFAT or NTFS.
"MBR is fine for a 4 TB boot disk."MBR tops out at 2 TiB; use GPT (UEFI).
"Share permissions alone control access."Over the network, the most restrictive of share and NTFS permissions applies.
"robocopy /MIR is just a copy."/MIR deletes destination files not in the source.
"chmod 777 fixes permission errors."It gives everyone write access: a security risk. Grant the minimum needed.
"Differential backups clear the archive bit."Only full and incremental backups clear it.
