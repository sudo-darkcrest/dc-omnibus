Running Azure and Microsoft 365

Why this matters. Azure Administrator and Microsoft 365 Administrator are both on the top-paying list, and they match some of the most common job titles in IT (Information Technology). This module turns the Azure Fundamentals knowledge from Module 27 into the day-to-day admin skills those exams test.

You will be able to

  • Describe the AZ-104 and MS-102 exams and how they renew.
  • Manage Entra ID users and groups, RBAC (Role-Based Access Control) scopes and governance.
  • Secure storage with keys, SAS (Shared Access Signature) tokens, RBAC and network rules.
  • Deploy resilient VMs (Virtual Machine) and configure VNets, NSGs, routing, Bastion, monitoring and backup.
  • Explain hybrid identity options, PIM, Defender XDR (Extended Detection and Response) and Purview controls.

2. AZ-104: identities and governance

  • Users and groups in Entra ID: security groups and Microsoft 365 groups; assigned or dynamic membership (rules such as department equals Sales). Guest users through B2B.
  • Self-service password reset (SSPR) reduces help desk calls; require two methods for admins.
  • Entra roles vs Azure roles: Entra roles (Global Administrator, User Administrator) manage the directory; Azure RBAC roles (Owner, Contributor, Reader, User Access Administrator) manage resources. They are separate systems.
  • RBAC scope: management group, subscription, resource group or resource. Assignments inherit downward. Custom roles are JSON (JavaScript Object Notation) lists of allowed actions (and NotActions).
  • Governance: Azure Policy (deny, audit, modify, deployIfNotExists), initiatives, resource locks, tags, management groups, and cost budgets and alerts (Module 27).
Exam trap. Contributor can create and delete resources but cannot grant access to others. Owner and User Access Administrator can.

3. AZ-104: storage administration

  • Storage account types: Standard general-purpose v2 (most uses) and premium accounts for block blobs, file shares or page blobs.
  • Redundancy: LRS, ZRS, GRS, GZRS and read-access versions (Module 27). You can change some options after creation.
  • Access, from broadest to narrowest:
    • Account access keys: full control; rotate them and avoid sharing.
    • Shared access signatures (SAS): time-limited, permission-limited URLs (Uniform Resource Locator). A stored access policy on a container lets you revoke many SAS tokens at once.
    • Entra ID with RBAC (for example Storage Blob Data Reader): the preferred method.
  • Network rules: storage firewall (allowed networks and IPs (Internet Protocol)), service endpoints and private endpoints.
  • Blob features: access tiers and lifecycle management rules, soft delete, versioning, immutability policies and object replication.
  • Azure Files shares over SMB/NFS (SMB: Server Message Block; NFS: Network File System); Azure File Sync caches them on Windows servers. Tools: AzCopy and Storage Explorer.

4. AZ-104: compute and networking

Compute

  • Availability sets spread VMs across fault domains (racks) and update domains in one data center. Availability zones spread VMs across buildings, giving a higher SLA (Service Level Agreement). Virtual Machine Scale Sets add autoscaling.
  • Deploy repeatably with ARM templates or Bicep; know how to read parameters, variables, resources and outputs.
  • Disks: managed disks (Standard HDD (Hard Disk Drive), Standard SSD (Solid-State Drive), Premium SSD, Ultra), encryption at rest by default, and Azure Disk Encryption for in-guest encryption.
  • App Service plans set the size and price tier for web apps; deployment slots allow swap-based releases. Azure Container Instances and Container Apps run containers without managing servers.

Networking

  • VNets and subnets, NSGs (rules processed by priority, lowest number first) and application security groups (group VMs by role inside NSG rules).
  • VNet peering (non-transitive by default), VPN Gateway, ExpressRoute, and user-defined routes to force traffic through a firewall.
  • Azure DNS (Domain Name System) public and private zones; Azure Bastion for browser-based RDP/SSH (RDP: Remote Desktop Protocol; SSH: Secure Shell) without public IPs on VMs.
  • Load Balancer (Layer 4) vs Application Gateway (Layer 7, with web application firewall).
  • Network Watcher: IP flow verify, next hop, connection troubleshoot and NSG flow logs.

5. AZ-104: monitoring, backup and recovery

  • Azure Monitor collects metrics (numbers over time) and logs (stored in a Log Analytics workspace, queried with KQL, the Kusto Query Language).
  • Alerts fire on metrics, logs or activity; action groups decide who is notified and what automation runs.
  • VM Insights and Application Insights give deeper views.
  • Azure Backup stores restore points in a Recovery Services vault or Backup vault with policies for frequency and retention; soft delete protects backups from deletion.
  • Azure Site Recovery replicates VMs to another region and orchestrates failover (disaster recovery, not backup).
A first KQL query: Heartbeat | where TimeGenerated > ago(1h) | summarize count() by Computer shows which VMs reported in the last hour.

6. MS-102: tenant and identity

Tenant setup

  • Add and verify a custom domain with a TXT record, then add MX, CNAME (Canonical Name record; autodiscover) and TXT (SPF) records so mail and clients work.
  • Assign licences directly or by group. Use admin roles with least privilege (for example Exchange Administrator, Helpdesk Administrator) and keep Global Administrators to a handful.
  • Watch Service health and the Message center for incidents and upcoming changes.

Hybrid identity

Sign-in methodHow it worksNotes
Password hash sync (PHS)A hash of the on-premises password hash is synced to Entra IDSimplest and most resilient; enables leaked-credential detection
Pass-through authentication (PTA)Sign-ins are checked live against on-premises domain controllers by agentsNo password data in the cloud, but depends on on-premises availability
Federation (for example AD (Active Directory) FS)Sign-ins redirect to an on-premises federation serviceMost complex; Microsoft encourages moving away from it

Synchronization uses Entra Connect Sync (a server you install) or the lighter Entra Cloud Sync.

Securing access

  • MFA (Multifactor Authentication) and Conditional Access (Module 27), with emergency "break-glass" accounts excluded and monitored.
  • Privileged Identity Management (PIM): admins activate roles just in time, for a limited period, with approval and justification.
  • Entra ID Protection: risk-based policies on user risk and sign-in risk.

Signals combine into incidents in the Defender portal. Microsoft Secure Score measures posture and suggests improvements.

Microsoft Purview compliance

  • Sensitivity labels classify and can encrypt or watermark documents and email.
  • Data loss prevention (DLP) policies detect sensitive information types (such as card numbers) and block or warn on sharing.
  • Retention policies and labels keep or delete content for set periods.
  • eDiscovery and audit support legal holds and investigations; insider risk management and communication compliance detect risky behaviour.
Exam trap. Sensitivity labels are about protection (who can open it). Retention labels are about lifecycle (how long to keep it).

Memory aids

Storage access, worst to best: Keys → SAS → Entra ID + RBAC.
VM resilience: Set = racks in one building; Zone = different buildings.
Hybrid sign-in, simplest to most complex: PHS → PTA → Federation.
Labels: Sensitivity = Secure it; Retention = Remember (or forget) it.
Exam trapWhy it is wrong
"Contributors can assign roles."Only Owner or User Access Administrator can.
"Entra roles manage VMs."Azure RBAC manages resources; Entra roles manage the directory.
"Site Recovery is backup."It's replication for DR; use Azure Backup for restore points.
