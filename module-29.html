Google Cloud

Why this matters. Google's Professional Cloud Architect is one of the highest-paying IT (Information Technology) certifications, and the Associate Cloud Engineer is on the same list. Google Cloud is the third major cloud, strong in data, Kubernetes and AI (Artificial Intelligence). Many employers run more than one cloud, so knowing how Google's model differs from AWS (Amazon Web Services) and Azure makes you more useful everywhere.

You will be able to

  • Describe the ACE and PCA exams and the Google Cloud resource hierarchy.
  • Apply IAM (Identity and Access Management) roles, service accounts and organization policies with least privilege.
  • Choose between Compute Engine, GKE, Cloud Run and functions.
  • Choose storage classes and databases including Cloud SQL (Structured Query Language), Spanner, Bigtable and BigQuery.
  • Design global VPC (Virtual Private Cloud) networking, hybrid links and security controls, and translate services between AWS, Azure and Google Cloud.

2. Resource hierarchy, IAM and billing

  1. Organization: the root node, tied to a Google Workspace or Cloud Identity domain.
  2. Folders: group projects by department or environment; can be nested.
  3. Projects: the basic container for resources, APIs (Application Programming Interface), quotas and billing. Every resource lives in exactly one project. Projects have a name, a globally unique project ID and a project number.
  4. Resources: VMs (Virtual Machine), buckets, databases.
  • IAM policies bind principals (users, groups, service accounts, domains) to roles on a resource. Policies inherit downward and are additive. Deny policies can override allows.
  • Role types: basic (Owner, Editor, Viewer: too broad for production), predefined (for example Compute Instance Admin) and custom.
  • Service accounts are identities for workloads. Attach them to VMs or services rather than downloading keys; use Workload Identity Federation for workloads outside Google Cloud.
  • Organization policies set guardrails such as allowed regions or "no external IPs (Internet Protocol) on VMs".
  • Billing accounts pay for projects. Set budgets and alerts, export billing data to BigQuery for analysis, and use labels for cost allocation.
Exam trap. Granting a role at the folder level gives it on every project in the folder. Removing it at the project level doesn't work, because policies are additive; use a deny policy or grant at a lower level instead.

Google Cloud is organised into regions and zones. Zonal resources (a VM, a persistent disk) live in one zone; regional resources (a regional MIG, regional storage) span zones; some are global (a VPC network, global load balancers).

Rule of thumb for exam questions: containers and stateless → Cloud Run; complex container platform → GKE; must control the OS → Compute Engine; tiny event code → functions.

5. Networking on Google Cloud

  • A VPC network is global; its subnets are regional. This differs from AWS, where a VPC is regional.
  • Firewall rules (and hierarchical firewall policies) apply to the VPC and target instances by network tags or service accounts. They are stateful.
  • Cloud NAT (Network Address Translation) gives private VMs outbound internet access. Private Google Access lets private VMs reach Google APIs.
  • Shared VPC: a host project owns the network and other projects use its subnets, giving central network control. VPC Network Peering connects separate VPCs (not transitive).
  • Cloud Load Balancing: global external Application Load Balancer (HTTP(S), with a single anycast IP worldwide), regional and network load balancers. Cloud CDN (Content Delivery Network) and Cloud Armor (WAF (Web Application Firewall) and DDoS protection) attach to it.
  • Hybrid: Cloud VPN (Virtual Private Network) (HA (High Availability) VPN gives a 99.99% SLA (Service Level Agreement) with correct setup) and Cloud Interconnect (Dedicated or Partner) for private links.
  • Identity-Aware Proxy (IAP) grants access to apps and VMs based on identity, without a VPN.

6. Operations, security and the gcloud CLI

  • gcloud is the main command-line tool (with gsutil/gcloud storage for buckets and bq for BigQuery). Cloud Shell gives a browser terminal with tools pre-installed.
  • Infrastructure as code: Terraform (widely used; Google's Infrastructure Manager runs it as a service).
  • Google Cloud Observability: Cloud Monitoring (metrics, uptime checks, alerting), Cloud Logging (log router, sinks to BigQuery or Cloud Storage), Cloud Trace and Error Reporting.
  • Security: Cloud KMS (Key Management Service) and customer-managed encryption keys, Secret Manager, Security Command Center (posture and threats), VPC Service Controls (perimeters that stop data exfiltration from services like BigQuery), and audit logs (admin activity logs are always on).
  • Google Cloud Architecture Framework: Google's equivalent of AWS Well-Architected, covering system design, operational excellence, security, reliability, cost optimization and performance.
Typical ACE task: gcloud compute instances create web-1 --zone=us-central1-a --machine-type=e2-medium creates a VM. Know how to set the default project and zone with gcloud config set.
