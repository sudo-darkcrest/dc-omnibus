Microsoft Azure and Microsoft 365

Why this matters. Microsoft runs the second-largest public cloud and the most common business email and office platform. Almost every IT (Information Technology) job touches Entra ID and Microsoft 365, and many touch Azure. This module covers the AZ-900 Azure Fundamentals exam, shows what help desk staff do in Microsoft 365, translates Azure into AWS (Amazon Web Services) terms, and maps out the Microsoft certifications worth considering.

You will be able to

  • Tell Azure, Microsoft 365 and Dynamics 365 apart, and explain shared responsibility.
  • Describe regions, availability zones, region pairs and the management group to resource hierarchy.
  • Choose the right compute, networking and storage service, including storage redundancy options.
  • Explain Entra ID, MFA (Multifactor Authentication), Conditional Access, RBAC (Role-Based Access Control) and Zero Trust.
  • Use Azure Policy, locks, tags, cost tools and SLAs (Service Level Agreement) to govern a cloud estate, and plan a Microsoft certification path.

1. The Microsoft cloud family

Microsoft sells three big cloud offerings that people often mix up. Knowing which is which is the first thing the AZ-900 (Azure Fundamentals) exam checks.

OfferingCloud modelWhat it gives youWho manages most of it
Microsoft AzureIaaS (Infrastructure as a Service) and PaaS (Platform as a Service; plus some SaaS (Software as a Service))Virtual machines, networks, storage, databases, AI and hundreds of other building blocksYou build and run your own systems on Microsoft's hardware
Microsoft 365SaaSEmail (Exchange Online), files (OneDrive, SharePoint), chat and meetings (Teams), Office apps, device managementMicrosoft runs the service; you manage users, settings and data
Dynamics 365 and Power PlatformSaaS and low-codeBusiness apps (sales, finance, field service) and tools to build apps and automations without much codeMicrosoft runs the platform; business teams build on it

All three share one identity system, Microsoft Entra ID (formerly Azure Active Directory). Sign in once and the same account, groups and security rules apply across Azure, Microsoft 365 and Dynamics.

Analogy. Azure is a huge hardware store where you buy parts and build your own house. Microsoft 365 is a fully furnished apartment: you just move in, decide who gets a key, and arrange the furniture.

Cloud concepts AZ-900 expects you to know

Module 20 covers cloud basics in depth. For AZ-900 the key ideas are:

  • Shared responsibility. The customer always owns their data, devices, accounts and identities. Microsoft always owns the physical data centers, hosts and network. Everything in between shifts towards Microsoft as you move from IaaS to PaaS to SaaS.
  • Public, private and hybrid cloud. Azure is public cloud. Azure Stack and Azure Arc help you run or manage Azure-style services in your own data center (hybrid).
  • Consumption-based pricing. You pay for what you use (operating expenditure, OpEx) instead of buying servers up front (capital expenditure, CapEx).
  • Benefits. High availability, scalability (vertical: bigger machine; horizontal: more machines), elasticity (scaling automatically with demand), reliability, predictability, security, governance and manageability.
  • Serverless. You supply code or a workflow and pay only when it runs; Microsoft manages servers entirely (Azure Functions, Logic Apps).

2. How Azure is organised: regions to resources

Azure is built in two directions: physical (where things run) and management (how you organise and control them).

Physical infrastructure

TermWhat it isWhy it matters
Data centerA building full of servers, power and cooling (see Module 23)You never pick one directly
RegionA geographic area with one or more data centers linked by a fast, low-latency network (for example East US or West Europe)You choose a region for each resource, based on users, laws and price
Availability zoneA physically separate group of data centers inside a region, with its own power, cooling and networkSpreading copies across zones protects against one building failing
Region pairTwo regions in the same geography, usually at least 300 miles apart, that Microsoft updates one at a timeUsed for disaster recovery and geo-redundant storage
Sovereign regionIsolated instances such as Azure Government (US) and Azure operated by 21Vianet (China)Meets strict legal or government requirements

Management hierarchy

  1. Management groups hold subscriptions so you can apply policy and access rules to many at once. They can be nested.
  2. Subscriptions are billing and access boundaries. Many companies have separate subscriptions for production, development and each department.
  3. Resource groups are folders for resources that share a lifecycle. Delete the resource group and everything in it is deleted. A resource belongs to exactly one resource group.
  4. Resources are the actual things: a virtual machine, a storage account, a database.

Every request to create or change something, whether from the portal, the command line, PowerShell or code, goes through Azure Resource Manager (ARM). ARM checks who you are, whether you're allowed, and which policies apply. Infrastructure as code tools (ARM templates, Bicep, Terraform) describe resources in a file so ARM can build them the same way every time.

Memory aid for the hierarchy, top to bottom: "My Small Red Robot": Management group, Subscription, Resource group, Resource. Settings flow downwards (inheritance).
Exam trap. A resource group can contain resources from different regions. The resource group's own region only stores its metadata.

Azure Kubernetes Service (AKS)Managed KubernetesYou run many containers and need orchestration (Module 20)
Azure FunctionsServerlessShort pieces of code that run when an event happens

Networking

  • Virtual network (VNet): your private network in Azure, split into subnets. VNet peering connects VNets privately.
  • VPN (Virtual Private Network) Gateway: encrypted tunnel to your office over the internet. ExpressRoute: a private dedicated connection that does not use the public internet.
  • Azure DNS (Domain Name System) hosts domain records. Load Balancer spreads traffic at Layer 4; Application Gateway at Layer 7 with a web application firewall; Front Door globally.
  • Network security groups (NSGs) are allow/deny rule lists on subnets or network cards. Azure Firewall is a managed, stateful firewall service. Azure DDoS Protection absorbs flood attacks.
  • Private endpoints give a PaaS service a private IP (Internet Protocol) inside your VNet so traffic never crosses the internet.

Storage

A storage account holds four main services: Blob (objects such as files, images and backups), Files (SMB/NFS file shares), Queue (messages between apps) and Table (simple NoSQL key-value data). VMs use managed disks.

RedundancyCopiesSurvives
LRS (Locally redundant)3 copies in one data centerA failed disk or server
ZRS (Zone-redundant)3 copies across availability zonesA whole data center or zone failing
GRS (Geo-redundant)LRS in the main region plus LRS in the paired regionA whole region failing
GZRS (Geo-zone-redundant)ZRS in the main region plus LRS in the paired regionA zone failure and a region failure

Add RA- (read access, as in RA-GRS) to let you read the secondary copy at any time. Blob access tiers trade storage price against access price: Hot (used often), Cool (30 days minimum), Cold (90 days) and Archive (180 days, offline, hours to restore).

Moving data in: AzCopy (command line), Azure Storage Explorer (desktop app), Azure File Sync (keeps Windows file servers in sync), Azure Migrate (assesses and moves servers) and Azure Data Box (a rugged physical device shipped to you for terabytes of data).

Databases

Azure SQL (Structured Query Language) Database (managed SQL Server), Azure Database for PostgreSQL and MySQL, and Azure Cosmos DB (globally distributed NoSQL with single-digit-millisecond reads).

4. Identity and security in Azure

In the cloud, identity is the new perimeter. Most breaches start with a stolen password, so Microsoft puts identity at the centre of its security story.

  • Microsoft Entra ID: the cloud directory for users, groups, devices and apps. It is not the same as on-premises Active Directory Domain Services; it uses web protocols (OAuth 2.0, OpenID Connect, SAML (Security Assertion Markup Language)) instead of Kerberos and Group Policy. Entra Connect syncs on-premises accounts to the cloud. Microsoft Entra Domain Services offers managed classic domain features for old apps.
  • Single sign-on (SSO): one sign-in for many apps.
  • Multifactor authentication (MFA): something you know plus something you have or are (Module 15). Passwordless options include Windows Hello, FIDO2 (Fast Identity Online 2) security keys and the Microsoft Authenticator app.
  • Conditional Access: if-then rules. "If a user signs in from an unknown country on an unmanaged device, then require MFA or block."
  • Azure role-based access control (RBAC): give people roles (Owner, Contributor, Reader, or specific built-in roles) at a scope (management group, subscription, resource group or resource). Permissions inherit downwards. Follow least privilege.
  • External identities: B2B lets partners sign in with their own accounts; B2C lets customers sign up to your apps.
Zero Trust is Microsoft's stated model: verify explicitly, use least-privilege access and assume breach. Defense in depth layers protections: physical, identity, perimeter, network, compute, application and data.

5. Governance, cost and monitoring

Keep things under control

  • Azure Policy: rules that resources must follow, such as "only these regions" or "every resource must have a cost-center tag". Policy can audit, deny or fix (remediate). Group policies into initiatives.
  • Resource locks: CanNotDelete stops deletion; ReadOnly stops any change. Locks apply even to Owners until removed.
  • Tags: name-value labels (Department = Finance) for cost reports, automation and ownership. Tags don't inherit by default; use Policy to enforce them.
  • Microsoft Purview maps and classifies data across the estate; the Service Trust Portal holds Microsoft's audit reports and compliance documents.
Exam trap. RBAC controls who can do things. Azure Policy controls what resources may look like. Locks stop accidents. Three different tools.

Understand and lower costs

  • Cost depends on resource type, size, region, usage time, data leaving Azure (egress; data going in is generally free) and the purchase model.
  • Pricing calculator: estimate the cost of new resources. TCO calculator (total cost of ownership): compare running servers yourself with Azure.
  • Microsoft Cost Management: see spending, set budgets and alerts, and split costs by tag.
  • Savings: reservations (commit for 1 or 3 years), savings plans, spot VMs (cheap spare capacity that can be taken away) and Azure Hybrid Benefit (reuse your existing Windows Server and SQL Server licences).

Service level agreements

An SLA is Microsoft's uptime promise, such as 99.9% or 99.99%, with service credits if missed. Running two VMs across availability zones gives a higher SLA than one VM. Combining services multiplies their SLAs, so the overall figure goes down: 99.9% × 99.9% ≈ 99.8%. Preview features usually have no SLA.

6. Microsoft 365 for IT support

Even if you never build in Azure, you will almost certainly support Microsoft 365. It is the most common office platform in business.

Common help desk tasks

  • Create a user in the Microsoft 365 admin center and assign a licence. No licence, no mailbox.
  • Reset a password or MFA method (or let users do it themselves with self-service password reset).
  • Give a colleague access to a shared mailbox or a SharePoint site using groups, not one-off permissions.
  • Offboard a leaver: block sign-in, revoke sessions, convert the mailbox to shared or hand OneDrive to a manager, then remove the licence.
  • Check the Service health page before troubleshooting a "Teams is down" call. It may be Microsoft, not you.
Rule of thumb: Microsoft 365 problems are usually licence, permission, sync or sign-in (MFA or Conditional Access). Check those four first.
