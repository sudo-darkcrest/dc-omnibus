Virtualization and Hyperconverged Infrastructure

Why this matters. Most organisations still run important workloads on their own virtualization clusters, and hyperconverged infrastructure has become the standard way to build them. Nutanix's professional certification is on the top-paying lists, and the same skills apply to VMware, Hyper-V and KVM (Kernel-based Virtual Machine). This module explains how clusters and HCI really work and how to run them safely.

  • Explain overcommitment, reservations and CPU (Central Processing Unit) ready time.

  • Describe the Nutanix platform components and the NCP-MCI exam.
  • Plan capacity, upgrades, networking and backups for a virtualization cluster.

1. Why private clouds still matter

Public cloud (Modules 23 and 25 to 29) gets the headlines, but most large organisations still run many workloads in their own data centers or at the edge: in hospitals, factories, shops and government sites. Those workloads run on virtualization clusters, and increasingly on hyperconverged infrastructure (HCI). Engineers who can run them are well paid, which is why Nutanix's professional certification (NCP-MCI) appears on top-paying lists.

  • Data has to stay put: laws, latency or sheer volume.
  • Predictable costs: steady workloads can be cheaper on owned hardware.
  • Legacy apps that can't easily move.
  • Hybrid and multicloud: the same management tools increasingly run across private and public clouds.

Module 8 introduced hypervisors and Module 23 covered cloud and storage basics. This module goes deeper into how virtualization clusters and HCI actually work.

What a cluster gives you

  • High availability (HA): if a host fails, its VMs restart automatically on other hosts. There is a short outage while they boot.
  • Live migration (vMotion in VMware): move a running VM to another host with no downtime, for maintenance or balancing.
  • Load balancing (VMware DRS (Distributed Resource Scheduler), Nutanix Acropolis Dynamic Scheduling): automatically spreads VMs to avoid hot spots.
  • Affinity rules: keep two VMs together (they talk a lot) or apart (two domain controllers shouldn't share a host).
  • Admission control and N+1: reserve enough spare capacity to survive one host failure. A 4-host cluster with N+1 should run at no more than about 75% of total capacity.

Resource management

  • Overcommitment: giving VMs more virtual CPUs or memory in total than the hardware has, betting they won't all be busy at once. CPU overcommit is common (for example 4 vCPUs (Virtual Central Processing Unit) per physical core); memory overcommit is riskier.
  • Reservations, limits and shares guarantee, cap or prioritise resources.
  • CPU ready time is how long a VM waits for a physical CPU. High ready time means too much overcommitment.

3. Hyperconverged infrastructure explained

Traditional "three-tier" infrastructure uses separate servers, a storage network (often Fibre Channel) and a SAN (storage area network) array. HCI combines compute and storage into identical nodes and uses software to pool the local disks of every node into one shared storage system.

Three-tierHyperconverged
Building blocksServers + SAN switches + storage arrayIdentical nodes with CPU, memory and local SSDs/NVMe (SSD: Solid-State Drive; NVMe: Non-Volatile Memory Express)
ScalingScale compute and storage separately, often in big stepsAdd a node; compute and storage grow together
ManagementSeparate teams and consolesOne console for VMs and storage
Best forVery large, specialised storage needsGeneral virtualization, VDI (Virtual Desktop Infrastructure; virtual desktops), remote sites, private cloud

How HCI protects data

  • Replication factor (RF): every write is copied to other nodes before it is acknowledged. RF2 keeps 2 copies (survives one node failure); RF3 keeps 3 (survives two) and needs at least 5 nodes in Nutanix.
  • Erasure coding: stores parity instead of full copies to save space, at some performance cost. Best for cold data.
  • Data locality: keeping a VM's data on the same node where it runs reduces network traffic.
  • Deduplication and compression reduce space used.
  • Self-healing: when a node or disk fails, the cluster rebuilds missing copies across the remaining nodes automatically.
Analogy. Three-tier is a restaurant with a separate kitchen, pantry and delivery van, each run by a different team. HCI is a row of food trucks, each with its own kitchen and pantry, sharing ingredients so the line keeps moving if one truck breaks down.

4. The Nutanix platform

  • Nutanix Cloud Infrastructure combines the storage software (AOS), a hypervisor (AHV, or ESXi / Hyper-V on supported hardware) and management.
  • Controller VM (CVM): a special VM on every node that runs the storage software and serves disks to the hypervisor. If a CVM fails, another node's CVM takes over its I/O.
  • Prism Element manages one cluster; Prism Central manages many clusters and adds automation, reporting and security features.
  • Foundation images and builds a new cluster. Life Cycle Manager (LCM) updates firmware and software one node at a time with no downtime.
  • Storage containers are logical pools with settings such as compression, deduplication and erasure coding.
  • Data protection: snapshots, asynchronous and near-synchronous replication to another site, synchronous replication for metro clusters, and runbook-driven disaster recovery.
  • Flow provides microsegmentation (firewall rules between VMs).
  • Nutanix Move migrates VMs from other hypervisors or clouds.

The NCP-MCI exam (verify)

Nutanix Certified Professional, Multicloud Infrastructure. Roughly 75 multiple-choice questions in 120 minutes, delivered online or at test centres. Topics: cluster configuration, storage, networking, VM management, data protection, security, and monitoring and troubleshooting. Nutanix offers a free on-demand course and a free community edition for practice. The certification is valid for two years.

Nutanix updates exam versions with each platform release; check nutanix.com for the current blueprint.

5. Virtual networking and storage protocols

  • Virtual switches connect VMs to each other and to physical uplinks. VLAN (Virtual Local Area Network) tags keep traffic separated (Module 12).
  • NIC (Network Interface Card) teaming / bonding combines physical network cards for bandwidth and failover (active-backup is simplest; LACP (Link Aggregation Control Protocol) needs switch support).
  • Separate networks for management, VM traffic, storage and live migration are best practice, even if they share physical links via VLANs.
  • Jumbo frames (MTU (Maximum Transmission Unit) 9000) can help storage traffic but must be set end to end.

6. Operating a cluster day to day

  • Capacity planning: watch CPU, memory and storage trends and keep N+1 headroom. Storage should usually stay below about 75 to 80% so rebuilds have room.
  • Upgrades: rolling, one node at a time; check compatibility lists for firmware, hypervisor and storage software.
  • Monitoring: latency (milliseconds per I/O), IOPS (input/output operations per second), throughput and CPU ready time tell you where the bottleneck is.
  • Backups are still needed: replication protects against hardware loss; backups protect against deletion, corruption and ransomware. Follow 3-2-1 (three copies, two media, one off-site), ideally with an immutable copy.
  • Security: harden hosts, restrict management networks, use role-based access, enable encryption at rest, and patch quickly.
Trap. "We have RF2 replication, so we don't need backups." Replication copies a deleted or encrypted file instantly to every copy.

7. Career path and related certifications

  • Start: A+ and Network+ (Modules 5 to 13), then Linux basics and a home lab with a free hypervisor.
  • Associate: Nutanix NCA (Nutanix Certified Associate) or VMware's associate-level certifications.
  • Professional: NCP-MCI; VMware VCP; Microsoft's Windows Server Hybrid Administrator.
  • Master and expert: Nutanix NCM-MCI (a hands-on lab exam) and NCX; VMware VCAP and VCDX.
  • Related roles: virtualization engineer, infrastructure engineer, private cloud engineer, VDI engineer.
Concepts transfer between platforms. If you understand HA, live migration, replication factor and capacity planning, switching from one vendor to another is mostly learning new screens.
