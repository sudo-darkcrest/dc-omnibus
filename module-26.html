AWS Beyond the Basics

Why this matters. Three of the twenty top-paying IT (Information Technology) certifications are AWS (Amazon Web Services) associate and specialty exams. They test whether you can design, build and secure real systems, not just name services. This module builds on Module 25 and covers the architecture, development and security knowledge those exams expect.

You will be able to

  • Describe the AWS certification ladder and the six Well-Architected pillars.
  • Design a VPC (Virtual Private Cloud) with public and private subnets, NAT (Network Address Translation), endpoints and correct security group and NACL (Network Access Control List) use.
  • Choose compute, storage and database services, including Multi-AZ versus read replicas.
  • Choose a disaster recovery strategy and decouple systems with SQS, SNS and EventBridge.
  • Apply IAM (Identity and Access Management) roles, policy evaluation, SCPs (Service Control Policy), KMS (Key Management Service) and AWS security services, and optimize cost.

The AWS Well-Architected Framework

Every architect question is really asking which answer best fits one or more of the six pillars: operational excellence, security, reliability, performance efficiency, cost optimization and sustainability.

2. Networking in depth: VPC design

  • A VPC (virtual private cloud) spans all Availability Zones in a Region. Subnets live in one AZ each.
  • A public subnet has a route to an internet gateway. A private subnet doesn't; instances there reach the internet outbound through a NAT gateway placed in a public subnet (one per AZ for resilience).
  • Security groups are stateful and attach to network interfaces; they only have allow rules. Network ACLs (Access Control List) are stateless, attach to subnets, have allow and deny rules, and are evaluated in number order.
  • VPC endpoints reach AWS services privately: gateway endpoints for S3 and DynamoDB (free, via route tables) and interface endpoints (PrivateLink) for most other services.
  • Connecting networks: VPC peering (one-to-one, not transitive), Transit Gateway (hub for many VPCs and on-premises links), Site-to-Site VPN and Direct Connect (private line).
  • Route 53 routing policies: simple, weighted, latency-based, failover, geolocation, geoproximity and multivalue.
  • CloudFront caches content at edge locations; Global Accelerator routes TCP/UDP (TCP: Transmission Control Protocol; UDP: User Datagram Protocol) traffic over AWS's network to the nearest healthy endpoint.
Exam trap. To block one specific bad IP (Internet Protocol) address, use a network ACL deny rule (or AWS WAF (Web Application Firewall)). Security groups can't deny.

3. Compute, storage and databases: choosing well

Compute

  • EC2 (Elastic Compute Cloud) instance families: general purpose (M, T), compute optimized (C), memory optimized (R, X), storage optimized (I) and accelerated (P, G, Inf, Trn).
  • Auto Scaling groups keep the right number of instances; Elastic Load Balancing: ALB (Layer 7, path and host routing), NLB (Layer 4, very high performance, static IPs) and Gateway Load Balancer (for security appliances).
  • Containers: ECS (Elastic Container Service) or EKS (Elastic Kubernetes Service), running on EC2 or serverless Fargate. Functions: Lambda (up to 15 minutes per run).

Storage

ServiceTypeUse
S3ObjectAny amount of files; classes Standard, Intelligent-Tiering, Standard-IA, One Zone-IA, Glacier Instant/Flexible/Deep Archive; lifecycle rules move data between them
EBS (Elastic Block Store)BlockDisks for one EC2 instance in one AZ (gp3 general purpose, io2 high IOPS); snapshots go to S3

Databases

  • RDS (Relational Database Service) Multi-AZ: a standby copy in another AZ for availability (automatic failover). Read replicas: extra copies for read scaling (and can be promoted for DR).
  • Aurora: AWS's MySQL/PostgreSQL-compatible database with six copies across three AZs; Aurora Serverless scales automatically.
  • DynamoDB: serverless key-value NoSQL with single-digit-millisecond reads; DAX adds an in-memory cache; global tables replicate across Regions.
  • ElastiCache (Redis or Memcached) caches frequent queries to take load off databases.

4. Resilient and decoupled architectures

Disaster recovery strategies

StrategyHowRecovery timeCost
Backup and restoreRestore from backups in another RegionHoursLowest

Warm standbyA scaled-down copy always runningMinutesMedium

Decoupling: let parts fail without breaking everything

  • SQS (Simple Queue Service): a queue between producers and consumers. Standard queues are at-least-once and best-effort ordering; FIFO queues keep order and exactly-once processing. A dead-letter queue catches messages that keep failing.
  • SNS (Simple Notification Service): publish once, deliver to many subscribers (fan-out).
  • EventBridge: an event bus with rules that route events between AWS services, SaaS (Software as a Service) apps and your code.
  • Step Functions: visual workflows that coordinate several steps with retries and error handling.
Exam pattern: "the application must not lose orders if the processing tier fails" almost always means put SQS between the tiers.

5. Developing on AWS

  • Credentials: code running on AWS should use an IAM role (instance profile, Lambda execution role, task role), never hard-coded access keys. Store secrets in Secrets Manager (with rotation) or Parameter Store.
  • SDKs and CLI: the SDK signs requests for you; handle throttling with exponential backoff and retries.
  • API (Application Programming Interface) Gateway fronts Lambda or other back ends with authentication (IAM, Cognito, Lambda authorizers), throttling, caching and stages.
  • DynamoDB design: choose a partition key with many distinct values to spread load; a sort key allows range queries; GSIs (global secondary indexes) support other access patterns. Prefer Query over Scan.
  • Lambda: set memory (which also scales CPU (Central Processing Unit)), timeout and concurrency; use layers for shared code; cold starts can be reduced with provisioned concurrency.
  • CI/CD (Continuous Integration / Continuous Delivery): CodeCommit or GitHub, CodeBuild (build and test), CodeDeploy (in-place, rolling, blue/green, canary), CodePipeline (orchestration). Infrastructure as code with CloudFormation, SAM (Serverless Application Model) or CDK.
  • Observability: CloudWatch logs and metrics, CloudWatch alarms, and X-Ray for tracing requests through distributed services.

6. Security Specialty: defending an AWS estate

Identity and governance

  • IAM policy evaluation: an explicit deny always wins; otherwise access needs an explicit allow; everything else is implicitly denied.
  • AWS Organizations with service control policies (SCPs) set the maximum permissions for whole accounts. Control Tower builds a governed multi-account landing zone.
  • Permission boundaries, resource-based policies (for example S3 bucket policies), and IAM Identity Center for workforce single sign-on.

Detection and response

Data and infrastructure protection

  • KMS (Key Management Service): customer managed keys, key policies, automatic rotation and envelope encryption. CloudHSM when you need a dedicated hardware security module.
  • S3 protection: Block Public Access, bucket policies, default encryption, versioning and Object Lock for immutability.
  • Edge protection: AWS WAF (web application firewall rules), Shield (DDoS; Advanced adds response team support) and Network Firewall.
  • Incident response automation: EventBridge rules trigger Lambda or Systems Manager runbooks, for example to isolate an instance by swapping its security group and snapshotting its disk for forensics.

7. Cost optimization and how to prepare

  • Purchase options: On-Demand, Savings Plans and Reserved Instances (1 or 3 years, big discounts for steady use), Spot (up to about 90% off; can be interrupted, so use for fault-tolerant work).
  • Right-size with Compute Optimizer; turn off non-production at night; use S3 lifecycle rules and Intelligent-Tiering; watch data transfer costs (cross-AZ and internet egress).
  • Tools: Cost Explorer, Budgets, Cost and Usage Reports, cost allocation tags.

A sensible order

  1. Cloud Practitioner (Module 25), optional if you already work in IT.
  2. Solutions Architect Associate: the broadest and most requested.
  3. Developer Associate if you write code, or SysOps/CloudOps if you run systems.
  4. Security Specialty after Security+ (Modules 16 to 18) and real AWS experience.
Build things. A free-tier account, a budget alarm set at a few dollars, and small projects (a static site on S3 with CloudFront, a serverless API with Lambda and DynamoDB) teach more than videos alone.
