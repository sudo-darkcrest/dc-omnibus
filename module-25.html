Amazon Web Services: AWS Cloud, Core Services and Certifications

Why this matters. AWS is the largest public cloud. Many of the data centers in Module 18 exist to run clouds like it, and many IT jobs now expect you to know its basic building blocks. Module 17 explained cloud in general; this module makes it concrete with AWS's own services, pricing and certifications, starting with the beginner-friendly AWS Certified Cloud Practitioner.

You will be able to

  • Explain Regions, Availability Zones and edge locations, and design for high availability.
  • Match common needs to core AWS services (compute, storage, databases, networking, security, monitoring).
  • Split security duties between AWS and the customer, and apply IAM best practices.
  • Choose the cheapest pricing option for a workload and name AWS's cost tools and support plans.
  • Plan an AWS certification path and know the Cloud Practitioner exam format.

Cert map

1. What AWS is and where it lives

Amazon Web Services launched in 2006 with S3 storage and EC2 virtual servers. Today it offers more than 200 services that you rent by the second, hour or request, instead of buying hardware. You click (or call an API) and minutes later you have servers, databases or AI models running in Amazon's data centers.

AWS is like a utility company for computing. You don't build a power station to switch on a light; you plug in and pay for what you use. AWS does the same for servers, storage and networks.
TermPlain meaningWhy it matters
RegionA geographic area, e.g., us-east-1 (N. Virginia), eu-west-2 (London)Pick for latency to users, data residency laws, price and which services are offered
Availability ZoneOne or more data centers with their own power and coolingRun in 2+ AZs so one failure doesn't take you down (high availability)
Edge locationA small site near usersFaster websites and DNS; also used by Shield for DDoS protection
Local Zone / Wavelength / OutpostsAWS closer to a city, inside 5G networks, or in your own buildingVery low latency or on-premises requirements
"Multi-AZ" and "multi-Region" are not the same. Multi-AZ protects against a data center failure (high availability). Multi-Region protects against a whole Region failing or serves users worldwide (disaster recovery and latency), at higher cost and complexity.

A quick way to remember the monitoring trio: CloudTrail = who did it (trail of footprints), CloudWatch = how is it doing (watching gauges), Config = how is it set up (configuration).

3. Security: shared responsibility and IAM

AWS secures the cloud itself: buildings, hardware, the hypervisor and its global network. You secure what you put in the cloud: your data, who can log in, operating system patches on EC2, firewall rules and encryption settings. The more managed the service, the more AWS does (see the Shared Responsibility Slider in Module 17).

Lock the root user

Turn on MFA, create no access keys for it, and use it only for the handful of tasks that need it.

Least privilege

Give each user, group or role only the permissions it needs. Use IAM roles for applications instead of storing keys in code.

Watch everything

Turn on CloudTrail in every Region, use GuardDuty for threats and Security Hub for one view of findings.

IAM policies are JSON documents that allow or deny actions (e.g., s3:GetObject) on resources. An explicit deny always wins. Service control policies (SCPs) in AWS Organizations set the maximum permissions for whole accounts.

4. Pricing, cost tools and support

Cloud turns big up-front purchases (CapEx) into pay-as-you-go running costs (OpEx). You pay mainly for compute time, storage used and data transferred out of AWS. Data coming in is generally free.

5. Designing well: the Well-Architected Framework

PillarAsk yourself
Operational excellenceCan we deploy, monitor and improve safely? (infrastructure as code, small changes)
SecurityLeast privilege, encryption, traceability, protect data in transit and at rest
ReliabilityDoes it recover from failure? (Multi-AZ, backups, Auto Scaling)
Performance efficiencyRight resource types, serverless where it fits, go global in minutes
Cost optimizationPay only for what you need; right-size; use the right pricing model
SustainabilityMinimise energy and resources used (added in 2021)

The AWS Cloud Adoption Framework (CAF) helps whole organizations move to the cloud through six perspectives: Business, People, Governance, Platform, Security and Operations. Migration strategies are often called the "7 Rs": retire, retain, rehost (lift and shift), relocate, repurchase, replatform and refactor.

Exam trapWhy it is wrong
"AWS patches my EC2 operating system."On EC2 you patch the OS. AWS patches the OS only on managed services such as RDS.
"CloudWatch shows who deleted the bucket."That's CloudTrail. CloudWatch is metrics, logs and alarms.
"Use Spot for the production database."Spot can be reclaimed at any time. Use On-Demand, Reserved or Savings Plans for steady, critical work.
"Security groups can deny traffic."Security groups only allow; NACLs can allow and deny.
"IAM is per Region."IAM is global.
