Security Foundations and Cryptography

Why this matters. Every security decision traces back to a few principles (confidentiality, integrity, availability, least privilege, zero trust) and a toolbox of controls and cryptography. Security+ Domain 1 (General Security Concepts) is built on exactly this, and the same ideas reappear in CISM (Certified Information Security Manager) and CISA (Certified Information Systems Auditor) as governance. The labs here use your browser's real Web Crypto engine.

You will be able to

  • Apply CIA, AAA (Authentication, Authorization, Accounting), non-repudiation, least privilege, defense in depth and zero trust.
  • Classify controls by category (technical, managerial, operational, physical) and type (preventive, detective…).
  • Explain MFA (Multifactor Authentication), SSO (Single Sign-On), SAML (Security Assertion Markup Language), OAuth 2.0, OIDC (OpenID Connect), Kerberos, RADIUS/TACACS (RADIUS: Remote Authentication Dial-In User Service; TACACS: Terminal Access Controller Access-Control System)+ and access control models.
  • Choose symmetric vs asymmetric crypto, hashing, salting and key stretching correctly.
  • Follow a certificate chain and a TLS (Transport Layer Security) 1.3 handshake, and explain where post-quantum crypto stands.

Cert map

1. Core security concepts

Confidentiality

Only authorized people can read it. Tools: encryption, access control, data classification.

Integrity

Data isn't altered without detection. Tools: hashing, digital signatures, change control.

Availability

Systems are up when needed. Tools: redundancy, backups, DDoS protection, patching.

  • AAA: Authentication (prove who you are), Authorization (what you may do), Accounting (logging what you did). Systems and devices authenticate too (certificates, keys).
  • Non-repudiation: the sender can't deny sending: digital signatures plus logs.
  • Least privilege: minimum access needed; defense in depth: layered controls so one failure isn't fatal.
  • Zero trust: "never trust, always verify." No implicit trust from network location. The control plane decides (policy engine, policy administrator; adaptive identity, threat scope reduction); the data plane enforces through a policy enforcement point (PEP) in front of each resource; implicit trust zones disappear.
  • Gap analysis: compare the current state with a target framework to find missing controls.
  • Deception: honeypot (fake system), honeynet (fake network), honeyfile, honeytoken (fake credential or record that alerts when used), DNS (Domain Name System) sinkholes.
  • Physical security basics: bollards, fencing, lighting, access badges, guards, cameras, access control vestibules (mantraps), sensors (infrared, pressure, microwave, ultrasonic).

Phishing-resistant MFA uses FIDO2/WebAuthn (FIDO2: Fast Identity Online 2): passkeys store a private key on your device; the server keeps only the public key, and the browser binds it to the real site's domain. 3. Cryptography essentials

Symmetric

One shared key encrypts and decrypts. Fast, for bulk data.

  • AES (Advanced Encryption Standard) (128/192/256-bit keys), modes: GCM (Galois/Counter Mode) (authenticated, preferred), CBC (Cipher Block Chaining; older).
  • ChaCha20-Poly1305: fast in software and on phones.
  • Problem: securely sharing the key, and n(n−1)/2 keys for n people.
  • Legacy/broken: DES (Data Encryption Standard), 3DES, RC4.

Asymmetric (public key)

A key pair: public key shared, private key kept secret. Slow; used for key exchange and signatures.

  • RSA (Rivest-Shamir-Adleman) (2048-bit minimum; 3072+ recommended).
  • ECC (Elliptic Curve Cryptography) (256-bit ECC ≈ 3072-bit RSA strength): ECDSA (Elliptic Curve Digital Signature Algorithm), Ed25519.
  • Diffie-Hellman / ECDHE (Elliptic Curve Diffie-Hellman Ephemeral): agree on a shared secret over an open channel; ephemeral keys give perfect forward secrecy.
Asymmetric encryption is a mailbox: anyone can drop a letter through the slot (public key), only the owner has the key to open it (private key). A digital signature is a wax seal only you can make, which anyone can check against your known seal design.

Hashing, salting and key stretching

A hash is a one-way, fixed-length fingerprint: the same input always gives the same output, and a tiny change flips about half the bits (the avalanche effect). Use SHA-256/SHA-384 (SHA: Secure Hash Algorithm) (SHA-2) or SHA-3. MD5 (Message Digest 5) and SHA-1 are broken: attackers can create collisions (two inputs with the same hash). HMAC (Hash-based Message Authentication Code) combines a hash with a secret key to prove integrity and authenticity.

Passwords are stored as salted, stretched hashes: a random salt per user defeats rainbow tables and makes identical passwords look different; key stretching (PBKDF2 (Password-Based Key Derivation Function 2), bcrypt, scrypt, Argon2) makes each guess slow.

Digital signatures

The sender hashes the message and encrypts the hash with their private key. Anyone decrypts it with the sender's public key and compares it to their own hash of the message. A match proves integrity, authenticity and non-repudiation.

4. PKI and certificates

A certificate (X.509) binds a public key to an identity, signed by a Certificate Authority (CA). Browsers trust a set of root CAs; roots sign intermediate CAs, which sign leaf (end-entity) certificates. A Registration Authority (RA) verifies identities for the CA. A CSR (certificate signing request) contains your public key and requested names.

5. Protecting data and keys

  • Data states: at rest (disk encryption, database TDE (Transparent Data Encryption)), in transit (TLS, IPsec (Internet Protocol Security), SSH (Secure Shell)), in use (memory; protected by secure enclaves and confidential computing).
  • Full-disk encryption (BitLocker, FileVault, LUKS (Linux Unified Key Setup)), partition, file, volume, database and record-level encryption.
  • TPM (Trusted Platform Module): chip in a computer that stores keys and measures boot integrity. HSM (Hardware Security Module): hardened appliance or cloud service for high-value keys (CAs, payments). Secure enclave: isolated processor area. KMS: key management service.
  • Obfuscation: steganography (hide data inside images/audio), tokenization (replace a card number with a random token; the mapping lives in a vault), data masking (show ****1234).
  • Blockchain: an append-only, distributed ledger where each block contains the previous block's hash; an open public ledger.

Post-quantum cryptography

A large quantum computer running Shor's algorithm would break RSA, Diffie-Hellman and ECC. Symmetric crypto and hashes are much less affected (use AES-256, SHA-384+). NIST published its first PQC standards in August 2024: FIPS (Federal Information Processing Standards) 203 ML-KEM (Module-Lattice-based Key Encapsulation Mechanism) (Kyber, key encapsulation), FIPS 204 ML-DSA (Module-Lattice-based Digital Signature Algorithm) (Dilithium, signatures) and FIPS 205 SLH-DSA (Stateless Hash-based Digital Signature Algorithm) (SPHINCS+, hash-based signatures). FN-DSA (Fast-Fourier Lattice-based Digital Signature Algorithm; Falcon) is being standardized as FIPS 206, and HQC (Hamming Quasi-Cyclic) was selected in 2025 as a backup KEM (Key Encapsulation Mechanism). "Harvest now, decrypt later" is why organizations are inventorying crypto and adopting hybrid key exchange (classical + ML-KEM) today. Check NIST for the latest status.

6. Choosing the right crypto tool

Cryptography questions usually boil down to: which tool solves this problem? Match the goal to the tool.

GoalToolExample
Keep data secret, fast, large amountsSymmetric encryptionAES-256 for disk encryption (BitLocker, FileVault)
Share a secret key with someone you've never metAsymmetric key exchangeElliptic-curve Diffie-Hellman inside TLS
Prove a file hasn't changedHashingSHA-256 checksum on a download
Prove who sent something and that it wasn't changedDigital signature (hash + private key)Signed software updates, signed email
Prove a website is genuineCertificate from a trusted certificate authorityThe padlock in your browser
Store passwords safelySlow, salted password hashingbcrypt, scrypt, Argon2, PBKDF2
Protect data in useSecure enclaves, confidential computingEncrypted memory regions in cloud servers

How the pieces fit in one HTTPS visit

  1. The server sends its certificate. Your browser checks the signature chain up to a trusted root.
  2. Browser and server use asymmetric key exchange to agree on a shared secret.
  3. That secret becomes a symmetric key, and AES or ChaCha20 encrypts the rest of the session quickly.
  4. Each message carries an integrity check so tampering is detected.
Encoding (like Base64) is not encryption. Anyone can decode it. Hashing is not encryption either: you cannot "decrypt" a hash.

7. Identity in real life: joiners, movers and leavers

Most identity failures are process failures. The joiner-mover-leaver process keeps accounts matched to real people and real jobs.

EventWhat should happenWhat goes wrong if skipped
Joiner (new hire)HR (Human Resources) triggers account creation with access based on role; MFA enrolled on day oneCopying a colleague's access gives far more than needed
Mover (changes job)New role's access added and old role's access removed"Privilege creep": years of leftover access
Leaver (leaves)Accounts disabled on the last day (immediately for dismissals), devices collected, shared passwords changedFormer staff can still log in
Periodic reviewManagers confirm each person's access every quarter or soNobody notices orphaned or excessive accounts
Auditors (Module 36) test this by picking a sample of leavers from HR records and checking that each account was disabled on time. It is one of the most common audit findings.

Exam trapWhy it is wrong
"Hashing is encryption."Hashes are one-way; encryption is reversible with a key.
"Encrypt with your private key for confidentiality."Anyone with your public key could read it; that's a signature, not secrecy.
"A password plus a security question is MFA."Both are knowledge factors.
