Cyber Security Careers: SOC Work, Attack Frameworks and Certifications

Why this matters. Modules 14 to 16 taught the security concepts behind Security+. This module shows what people actually do with them: watching for attacks in a security operations center, hunting intruders, testing defences, fixing vulnerabilities and managing risk. It explains the frameworks professionals use every day and lays out the certification paths, so you can choose a direction and know which exam to take next.

You will be able to

  • Describe the main cyber security roles and how people move between them.
  • Explain an attack using the Cyber Kill Chain and MITRE ATT&CK.
  • Triage security alerts and describe SOC tools (SIEM (Security Information and Event Management), SOAR (Security Orchestration, Automation and Response), EDR (Endpoint Detection and Response)) and metrics.
  • Prioritise vulnerabilities using CVSS (Common Vulnerability Scoring System), exploitation data, exposure and asset value.
  • Choose a certification path, including CySA+, PenTest+, OSCP (OffSec Certified Professional) and CISSP (Certified Information Systems Security Professional), and practise skills legally.

Cert map

1. Cyber security jobs

Cyber security isn't one job. It's a family of roles that defend, attack (with permission), investigate, engineer and govern. Most people start in IT (Information Technology) support, networking or a SOC and move toward a specialty.

2. How attacks unfold

Defenders use models to break an attack into stages. Each stage is a chance to detect and stop it, and the earlier the better.

MITRE ATT&CK goes further. It's a free, constantly updated catalogue of what real attackers do, organised as tactics (the attacker's goal at each step) containing techniques (how they do it, e.g., T1566 Phishing, T1059 Command and Scripting Interpreter). The Enterprise matrix has 14 tactics:

TacticAttacker's goalExample technique
ReconnaissanceGather information for planningSearch victim-owned websites, scan for open ports
Resource DevelopmentGet infrastructure and toolsRegister look-alike domains
Initial AccessGet into the networkPhishing, exploiting a public-facing application
ExecutionRun malicious codePowerShell, user opening a malicious file
PersistenceStay in after rebootsScheduled task, new account, registry run key
Privilege EscalationGet higher permissionsExploit a vulnerable driver, abuse misconfigured sudo
Defense EvasionAvoid being detectedDisable security tools, clear logs
Credential AccessSteal passwords and tokensCredential dumping (e.g., from LSASS (Local Security Authority Subsystem Service)), brute force
DiscoveryLearn the environmentList domain users and network shares
Lateral MovementMove to other systemsRemote Desktop, pass-the-hash
CollectionGather the target dataArchive files, capture screenshots
Command and ControlTalk to compromised systemsHTTPS (HyperText Transfer Protocol Secure) beaconing, DNS (Domain Name System) tunnelling
ExfiltrationSteal the dataUpload to cloud storage
ImpactDisrupt or destroyRansomware encryption, wiping data
The Diamond Model describes each intrusion event by four linked points: adversary, capability (malware, exploits), infrastructure (IPs (Internet Protocol), domains) and victim. Finding one point helps you pivot to the others.

3. Inside a security operations center

Tools

SIEM collects and correlates logs. EDR/XDR (XDR: Extended Detection and Response) watches endpoints and more. SOAR automates playbooks. Threat intelligence feeds add context. Ticketing tracks every case.

Alert outcomes

True positive: a real attack, so respond. False positive: a false alarm, so close it and tune the rule. False negative: missed entirely, the worst case, found by threat hunting or after damage.

Metrics

MTTD (mean time to detect), MTTR (mean time to respond or recover), alert volume, false positive rate, and dwell time (how long attackers stayed undetected).

Incident response follows the NIST (National Institute of Standards and Technology) phases from Module 16: preparation; detection and analysis; containment, eradication and recovery; and post-incident activity (lessons learned). NIST SP (Special Publication) 800-61 Rev. 3 (2025) now aligns these with the CSF (Cybersecurity Framework) 2.0 functions (verify).

4. Vulnerability management

Every organisation has more vulnerabilities than time to fix them, so the skill is prioritising. The cycle: discover assets, scan (authenticated scans see more), prioritise, remediate (patch, reconfigure, or apply a compensating control), verify with a rescan, and report.

SignalWhat it tells you
CVE (Common Vulnerabilities and Exposures)The unique ID (Identification) of the flaw, e.g., CVE-2021-44228 (Log4Shell)
CVSS (0–10)Technical severity: attack vector, complexity, privileges needed, user interaction, impact. 9.0+ critical, 7.0–8.9 high
CISA KEV (Known Exploited Vulnerabilities)Attackers are exploiting it right now. Treat as urgent
EPSS (Exploit Prediction Scoring System) (0–100%)Probability it will be exploited in the next 30 days
Exposure and asset valueIs it internet-facing? Does the system hold crown-jewel data or run critical services?
"Highest CVSS first" is a classic exam and real-world mistake. A CVSS 7.5 on an internet-facing server that attackers are actively exploiting beats a CVSS 9.8 on an isolated lab machine.

6. Getting started the right way

Build a home lab

A spare PC (Personal Computer) or free virtualisation (Module 8) with a few VMs (Virtual Machine): a Windows machine, a Linux server, a firewall VM and a free SIEM. Attack your own machines, then find the evidence in the logs.

Practise legally

Use CTF competitions and training platforms built for practice, plus deliberately vulnerable VMs. Only ever test systems you own or have written permission to test.

Show your work

Write up what you did and learned. Contribute detection rules or scripts. Join local security meetups and conferences (BSides events are cheap and friendly).

Good intentions are not a legal defence. Scanning or logging into systems without permission is a crime in most countries, under laws such as the US Computer Fraud and Abuse Act and the UK Computer Misuse Act, even if you only wanted to help.

7. A day on a SOC shift

What does an entry-level security analyst actually do all day? Here is a typical shift in a security operations center.

TimeActivity
08:00Shift handover. The night team explains open cases: a suspicious login still being investigated and a noisy alert rule.
08:30Alert queue. Review new SIEM alerts. Most are benign: a user travelling, an admin running a scheduled script.
10:15Real finding. A laptop contacts a domain registered two days ago. EDR shows a macro-enabled document launched PowerShell. The analyst isolates the laptop and escalates to tier 2.
11:30Tuning. Adjusts the noisy rule so it ignores a known backup server, cutting false positives without hiding real threats.
13:00Threat intel. Reads a new advisory about an exploited VPN (Virtual Private Network) flaw and searches logs for its indicators.
14:30Phishing reports. Users reported five emails. Two are real phishing; the analyst blocks the sender and removes copies from mailboxes.
16:00Documentation. Writes up each case: what happened, evidence, actions, and whether a rule or process should change.
The skills that make analysts stand out are curiosity, careful notes, and clear writing for people who are not technical. Practise by writing short reports on each lab you complete.

8. Building a portfolio that gets interviews

Security hiring managers like evidence. A small portfolio shows what certifications can't.

  • Home lab write-ups: set up a free SIEM, send it logs from a Windows and a Linux virtual machine, simulate a failed-login attack and show how you detected it.
  • Detection rules: publish a few simple detection rules with an explanation of what they catch and what false positives to expect.
  • Capture-the-flag results: beginner-friendly CTFs and training platforms provide legal, safe practice environments.
  • Scripts: a short Python or PowerShell script that parses logs or checks for weak settings.
  • A short blog or notes explaining something you learned in plain language.
Only practise attack techniques on systems you own or platforms built for it. Scanning or attacking systems without written permission is illegal in most countries, even "just to test".
