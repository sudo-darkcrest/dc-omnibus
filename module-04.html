Inside the Machine: How a Computer Actually Works

Why this matters. Troubleshooting is guessing unless you know what the machine is doing. Why does adding RAM (Random Access Memory) speed up a slow PC (Personal Computer) but a faster CPU (Central Processing Unit) does not? Why does a laptop fail to boot with "no bootable device"? Why is an SSD (Solid-State Drive) so much faster than a hard drive? Every one of these is answered by how the CPU, memory, buses and firmware work together. A+ Core 1 tests the parts; this module explains the machine they form.

You will be able to

  • Describe the von Neumann model and why modern CPUs use split (Harvard-style) L1 caches.
  • Name the parts of a CPU and walk through the fetch-decode-execute cycle step by step.
  • Explain pipelining, superscalar and out-of-order execution, branch prediction, cores and SMT (Simultaneous Multithreading).
  • Rank the memory hierarchy by size and speed and explain cache hits and misses.
  • List the stages of the boot process and the symptom you would see if each one failed.
  • Explain what GPUs (Graphics Processing Unit), NPUs (Neural Processing Unit) and other accelerators are good at.

1. The von Neumann model

Almost every computer follows the design described by John von Neumann in 1945. It has four parts connected by buses (shared sets of wires that carry signals between components):

The key idea is the stored program: instructions are just numbers in memory, the same as data. That makes computers general purpose (load a different program and it does a different job) but creates the von Neumann bottleneck: instructions and data compete for the same path to memory.

The Harvard architecture uses separate memories and buses for instructions and data, so both can be fetched at once. Microcontrollers often use it. Modern CPUs are a hybrid: one unified main memory (von Neumann), but split L1 instruction and L1 data caches inside the core (Harvard style), so the core can fetch an instruction and load data in the same cycle.

2. The CPU in detail

A chef in a kitchen. The recipe book is RAM. The control unit is the chef reading the next step. The ALU (Arithmetic Logic Unit) is the chopping board where work happens. Registers are the chef's hands: tiny, but instant. The clock is a metronome: one beat, one small action.

The fetch-decode-execute cycle

  1. Fetch: the PC's address goes out on the address bus; memory returns the instruction on the data bus; it is placed in the IR; the PC is incremented.
  2. Decode: the control unit splits the instruction into an opcode (what to do) and operands (what to do it to).
  3. Execute: the ALU computes, or data moves between registers and memory, or the PC is changed (a jump).
  4. Repeat, billions of times a second.

Instruction sets

An instruction set architecture (ISA) is the list of instructions a CPU understands; software compiled for one ISA will not run natively on another.

ISAStyleWhere you find it
x86-64 (AMD64 / Intel 64)CISC (Complex Instruction Set Computer): many complex, variable-length instructions (internally translated into simpler micro-ops)Most PCs and servers (Intel, AMD)
ARM (AArch64)RISC (Reduced Instruction Set Computer): fewer, simpler, fixed-length instructionsPhones, tablets, Apple silicon Macs, many cloud servers (AWS (Amazon Web Services) Graviton)
RISC-VRISC, open and royalty-freeMicrocontrollers, storage controllers, growing in many devices
CISC vs RISC today is about the visible instruction set, not performance: modern x86 cores decode CISC instructions into RISC-like micro-operations, and modern ARM cores are just as sophisticated inside. RISC designs tend to be simpler to decode and more power efficient.

Making it faster

  • Pipelining: overlap stages of different instructions like an assembly line (fetch the next while decoding this one). See Lab 2.
  • Superscalar: several execution units, so more than one instruction completes per cycle.
  • Branch prediction: guess which way an if will go and start work early; a wrong guess forces a pipeline flush.
  • Out-of-order execution: run instructions whose inputs are ready while others wait for memory, then retire results in program order.
  • Cores: complete processors on one chip. A 16-core CPU can run 16 instruction streams at once.
  • Threads and SMT: a thread is a single sequence of instructions. Simultaneous multithreading (Intel calls it Hyper-Threading) lets one core run two threads by sharing execution units, typically a 15 to 30% gain, not double.
  • Clock speed vs IPC: performance ≈ clock speed × instructions per cycle (IPC). A 3.5 GHz CPU with higher IPC can beat a 4.5 GHz older design.
"More GHz always means faster." Not across generations or architectures: IPC, core count, cache size and memory speed all matter.

3. The memory hierarchy

Fast memory is expensive and small; cheap memory is big and slow. Computers stack several kinds so the data you need most is in the fastest place. A cache is a small, fast memory holding copies of recently or frequently used data. A cache hit means the data was found there; a miss means going to a slower level.

Caches work because programs show locality: they reuse recent data (temporal locality) and use data near recent data (spatial locality), so caches fetch whole 64-byte lines at a time.

RAM basics

  • Every byte of RAM has an address. A 64-bit CPU can address far more than any machine has installed; a 32-bit system is limited to 4 GiB (232 bytes).
  • RAM is volatile: it loses its contents without power. Storage (SSD, HDD (Hard Disk Drive)) is non-volatile.
  • DRAM stores each bit as charge in a tiny capacitor that leaks, so it is refreshed thousands of times a second; dense and cheap. SRAM uses six transistors per bit, needs no refresh, and is fast but expensive: used for caches.
  • DDR (double data rate) SDRAM (Synchronous Dynamic Random Access Memory) transfers data on both clock edges. Generations (DDR3, DDR4, DDR5) are not interchangeable: different voltages and notch positions (Module 5). DDR5 has two independent 32-bit subchannels per module and on-die ECC (Error-Correcting Code).
  • Channels: each memory channel is an independent 64-bit path. Dual channel doubles bandwidth if DIMMs (Dual Inline Memory Module) are installed in matching slots.

4. Buses and interconnects

  • Front-side bus (history): until about 2008, the CPU reached RAM through a northbridge chip over the FSB, a bottleneck.
  • Integrated memory controller: today the memory controller sits on the CPU itself, so RAM connects directly to the processor.
  • PCI (Peripheral Component Interconnect) Express (PCIe): a serial point-to-point link made of lanes (one pair to send, one to receive). Slots are x1, x4, x8 or x16. Each generation roughly doubles per-lane bandwidth: Gen 3 ≈ 1 GB/s (GB: Gigabyte) per lane, Gen 4 ≈ 2 GB/s, Gen 5 ≈ 4 GB/s, Gen 6 ≈ 8 GB/s (each direction).
  • Chipset (Platform Controller Hub on Intel): connects slower devices (USB (Universal Serial Bus), SATA (Serial Advanced Technology Attachment), extra PCIe lanes, audio, networking) to the CPU over a dedicated link.
  • DMA (direct memory access): devices such as NICs (Network Interface Card) and disk controllers copy data straight to RAM without the CPU moving every byte, freeing the CPU.

5. The boot process

  1. Power on: the power supply starts and stabilizes its voltages, then sends a Power Good (PWR_OK) signal to the motherboard.
  2. Firmware starts: the CPU begins executing firmware (UEFI (Unified Extensible Firmware Interface), or legacy BIOS (Basic Input/Output System)) from flash on the motherboard.
  3. POST (power-on self-test): firmware checks CPU, RAM, video and key devices. Failures produce beep codes or LED/POST (LED: Light-Emitting Diode) codes.
  4. Find a boot device: firmware follows the boot order. UEFI reads the EFI (Extensible Firmware Interface) System Partition on a GPT (GUID Partition Table; GUID (Globally Unique Identifier) Partition Table) disk; legacy BIOS reads the MBR (Master Boot Record). Secure Boot checks the bootloader's digital signature.
  5. Bootloader (Windows Boot Manager, GRUB (Grand Unified Bootloader)): loads the OS (Operating System) kernel.
  6. Kernel: initializes memory management and drivers, mounts the root file system.
  7. OS services start (Windows services, Linux systemd units).
  8. Login: the user signs in and their profile loads.

6. Interrupts and how the OS shares the CPU

An interrupt is a signal that makes the CPU pause what it is doing, run a small handler and then resume. Hardware interrupts come from devices (a key press, a packet arriving, a disk finishing); software interrupts and exceptions come from programs (a system call, a divide by zero, a page fault).

  • A process is a running program with its own memory space. A thread is a path of execution inside a process; threads share the process's memory.
  • The OS scheduler decides which thread runs on each core. A timer interrupt fires many times a second so the OS can switch (preemptive multitasking).
  • A context switch saves one thread's registers and loads another's. It costs time, so too many runnable threads hurt performance.

7. GPUs, NPUs and other accelerators

A CPU has a few powerful cores good at complex, branching tasks. An accelerator is a processor specialized for one kind of work.

  • GPU (graphics processing unit): thousands of simpler cores doing the same math on lots of data at once. Built for graphics, now central to AI (Artificial Intelligence) training and inference and scientific computing. Has its own fast memory (GDDR (Graphics Double Data Rate) or HBM (High Bandwidth Memory)).
  • NPU (neural processing unit): low-power AI inference engine in phones and laptops ("AI PCs"), measured in TOPS (trillions of operations per second).
  • Others: TPUs (Tensor Processing Unit) and other AI ASICs (Application-Specific Integrated Circuit), FPGAs (Field-Programmable Gate Array; reprogrammable logic), DPUs/SmartNICs (DPU: Data Processing Unit; offload networking and storage in data centers), video encoders, crypto engines (AES-NI instructions), and the TPM (Trusted Platform Module) security chip (Module 16).

8. Tracing a tiny program by hand

The simulator in Lab 5 runs a program automatically. Doing it once by hand makes every later idea (cache, pipelines, clock speed) easier to picture. Here is a four-instruction program that adds two numbers.

AddressContentsMeaning
0LOAD 6Copy the value at address 6 into the accumulator
1ADD 7Add the value at address 7 to the accumulator
2STORE 8Copy the accumulator into address 8
3HALTStop
67Data
75Data
80The answer goes here
  1. Fetch: the program counter says 0. The CPU reads "LOAD 6" from RAM (Random Access Memory) into the instruction register and moves the program counter to 1.
  2. Decode: the control unit sees LOAD and knows it must read memory.
  3. Execute: it reads address 6 (the value 7) into the accumulator. Accumulator = 7.
  4. Repeat for ADD 7: the ALU (Arithmetic Logic Unit) adds 5. Accumulator = 12.
  5. STORE 8 writes 12 back to RAM. HALT stops the clock.

Notice that instructions and data live in the same memory. That is the von Neumann architecture, and it is why a bug that writes to the wrong address can overwrite program code, which attackers exploit in buffer overflows (Module 17).

A real 4 GHz CPU does this four billion times a second per core, and modern cores overlap the steps (pipelining) and run several instructions at once, so they finish more than one instruction per tick.

9. Why is my computer slow? Thinking like the hardware

Most "slow computer" complaints come down to one part waiting for another. Knowing which part is the bottleneck tells you what to upgrade.

A computer is a kitchen. The CPU is the chef, RAM is the counter space, and storage is the pantry. A fast chef with a tiny counter keeps walking to the pantry. More counter space (RAM) often helps more than a faster chef.
