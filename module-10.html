IP Addressing and Subnetting, Made Visual

Why this matters. Every device that talks on a network needs an address, and every network engineer must be able to carve address space into subnets quickly and correctly. Subnetting is the single most feared Network+ topic, and it only takes practice. DHCP (Dynamic Host Configuration Protocol) and DNS (Domain Name System) problems are behind a huge share of real help desk tickets.

You will be able to

  • Read an IPv4 (Internet Protocol version 4) address and mask in binary and find the network, broadcast and usable host range.
  • Subnet with the "magic number" method in your head, and design a VLSM (Variable Length Subnet Masking) plan.
  • Recognize private, APIPA (Automatic Private Internet Protocol Addressing), loopback and special ranges, and explain NAT (Network Address Translation) and PAT (Port Address Translation).
  • Compress and expand IPv6 (Internet Protocol version 6) addresses and name the IPv6 address types.
  • Step through DHCP DORA (Discover, Offer, Request, Acknowledge) and a DNS lookup, and pick the right DNS record type.

1. IPv4 addresses

An IPv4 address is 32 bits, written as four 8-bit octets in decimal: 192.168.10.37. The subnet mask says which bits are the network part and which are the host part. CIDR (Classless Inter-Domain Routing) notation writes the mask as a count of network bits: /24 = 255.255.255.0.

An IP (Internet Protocol) address is like a phone number: the area code (network bits) says which region; the rest (host bits) picks one phone. The mask tells you where the area code ends.

2. Subnetting step by step

In every subnet: the first address is the network address (all host bits 0), the last is the broadcast address (all host bits 1), and everything between is usable. With h host bits: usable hosts = 2h − 2. Borrowing s bits makes 2s subnets.

The magic number method

  1. Find the interesting octet: the one where the mask is not 255 or 0.
  2. Magic number (block size) = 256 − mask value in that octet. For /26, the mask is 255.255.255.192, so 256 − 192 = 64.
  3. Subnets start at multiples of the magic number: 0, 64, 128, 192.
  4. Find the multiple at or below your IP's octet: that's the network. The next multiple minus 1 is the broadcast.
Example: 192.168.1.100/26. Magic number 64. Multiples: 0, 64, 128. 100 falls in the 64 block. Network 192.168.1.64, broadcast 192.168.1.127, hosts .65 to .126 (62 usable).
CIDRMaskMagic #AddressesUsable hosts

VLSM and supernetting

VLSM (Variable Length Subnet Masking) uses different mask lengths inside one block so each subnet fits its needs: a /30 or /31 for a point-to-point link, a /24 for a big department. Always allocate the largest subnet first so blocks stay aligned. Supernetting (route summarization) goes the other way: 192.168.0.0/24 + 192.168.1.0/24 = 192.168.0.0/23, one route instead of two.

4. IPv6

IPv6 addresses are 128 bits written as eight groups of four hex digits: 2001:0db8:0000:0000:0000:ff00:0042:8329. Two shortening rules: (1) drop leading zeros in any group (0db8 → db8, 0000 → 0); (2) replace one run of consecutive all-zero groups with ::, only once per address (use it on the longest run). Result: 2001:db8::ff00:42:8329.

  • SLAAC (Stateless Address Autoconfiguration): the host takes the /64 prefix from a router advertisement and builds its own interface ID (Identification), so no DHCP server is needed. DHCPv6 can still supply DNS or full stateful addressing.
  • EUI-64 (Extended Unique Identifier 64-bit): builds the 64-bit interface ID from the 48-bit MAC (Media Access Control) by inserting FFFE in the middle and flipping the 7th bit. Many OSes now use random (privacy) IDs instead.
  • Dual stack: run IPv4 and IPv6 side by side (the preferred transition). Tunneling (6to4, Teredo, GRE (Generic Routing Encapsulation)) carries IPv6 inside IPv4. NAT64/DNS64 (NAT64: Network Address Translation from IPv6 to IPv4; DNS64: Domain Name System translation for IPv6-only clients) lets IPv6-only clients reach IPv4 servers.
  • Standard LAN (Local Area Network) subnet: /64. Sites typically receive a /48 or /56.

5. DHCP and DNS

DHCP: DORA

DHCP (Dynamic Host Configuration Protocol, UDP (User Datagram Protocol) 67 server/68 client) hands out IP address, mask, default gateway, DNS servers and lease time in four messages: Discover (client broadcast), Offer (server), Request (client broadcast, so other servers know), Acknowledge (server). A scope is the address pool; exclusions keep static devices out of it; reservations tie a MAC to a fixed IP. Clients try to renew at 50% of the lease (T1) and rebind at 87.5% (T2). Because Discover is a broadcast, routers block it; a DHCP relay (Cisco: ip helper-address) forwards it to a server on another subnet.

A recursive query asks the resolver "get me the final answer". The resolver then makes iterative queries: root servers → TLD (Top-Level Domain) servers (.com) → the domain's authoritative server, and caches the result for its TTL (Time To Live). DNSSEC (Domain Name System Security Extensions) signs records so resolvers can verify they weren't forged. DoH (DNS over HTTPS (HyperText Transfer Protocol Secure), port 443) and DoT (DNS over TLS (Transport Layer Security), port 853) encrypt queries for privacy.

6. Subnetting step by step: a worked office plan

Subnetting becomes easy once you have done one real plan. Here is a typical exam-style task.

Task: A company has the network 192.168.10.0/24 and needs four separate subnets: Staff (50 hosts), Guests (25 hosts), Servers (10 hosts) and a router link (2 hosts). Use VLSM (Variable Length Subnet Masking) so nothing is wasted.

  1. Sort by size, largest first. Staff 50, Guests 25, Servers 10, Link 2.
  2. Find the smallest block that fits each one. Usable hosts = 2host bits − 2 (one address for the network, one for broadcast).
    • 50 hosts → 64-address block (/26, 62 usable)
    • 25 hosts → 32-address block (/27, 30 usable)
    • 10 hosts → 16-address block (/28, 14 usable)
    • 2 hosts → 4-address block (/30, 2 usable)
  3. Lay the blocks out in order.
SubnetNetworkMaskUsable rangeBroadcast
Staff192.168.10.0/26255.255.255.192.1 to .62.63
Guests192.168.10.64/27255.255.255.224.65 to .94.95
Servers192.168.10.96/28255.255.255.240.97 to .110.111
Router link192.168.10.112/30255.255.255.252.113 to .114.115

Addresses .116 to .255 are left free for growth. The default gateway for each subnet is usually its first usable address (.1, .65, .97).

The "magic number" shortcut: subtract the interesting mask octet from 256. For /27 the mask is 224, so 256 − 224 = 32, and subnets start at 0, 32, 64, 96 and so on.

7. Reading IP problems from the symptoms

Most addressing problems leave a clear fingerprint. Learn to read the address before you touch anything.

What you seeWhat it meansNext step
Address starts with 169.254APIPA: the device could not reach a DHCP serverCheck the cable or Wi-Fi, then the DHCP server and its scope
Correct IP, but can't reach other networksMissing or wrong default gatewayCompare the gateway with the router's address
Can reach some local devices but not othersWrong subnet maskCompare masks across devices
"IP address conflict" warningTwo devices have the same address, often one static and one from DHCPExclude static addresses from the DHCP scope
IPv6 address starts with fe80::Link-local only; normal, but no global address means no IPv6 router advertisementCheck the router's IPv6 settings
Names don't resolve, IPs workDNS server wrong or downnslookup and check DNS settings
A device with a 169.254 address is not "on the wrong network". It never got an address at all. Fix the path to the DHCP server.

    Memory aids

    Mask values in order: 128, 192, 224, 240, 248, 252, 254, 255. Say it like a phone number: "one-twenty-eight, one-ninety-two, two-twenty-four…"
    Powers of two you need: 2, 4, 8, 16, 32, 64, 128, 256. Hosts = 2h − 2 ("minus the two bookends: network and broadcast").

    172.16 to 172.31: "sixteen to thirty-one is private fun."
    Exam trapWhy it is wrong
    "172.32.0.1 is private."The private /12 ends at 172.31.255.255.
    "A /30 has 4 usable hosts."4 addresses, 2 usable. (/31 is a special case for point-to-point links: 2 usable, RFC 3021.)
    "Use :: twice to shorten more."Only one :: is allowed, or the address becomes ambiguous.
    "169.254.x.x means the network is fine."APIPA means DHCP failed; check cabling, VLAN and the DHCP server or relay.
    "PTR records map names to IPs."PTR is reverse (IP → name); A/AAAA are forward.
